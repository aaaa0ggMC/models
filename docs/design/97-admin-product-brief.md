## 0. 阅读指引

### 0.1 这篇文档是什么

一份**产品与风格简报**：写给下一个设计者（人或 Agent），让它在动手之前先知道这个产品
要解决谁的什么问题、信息该怎么组织、看着该是什么气质、以及哪些行为是主人已经拍过板、
不许再商量的。

它不是实现方案：不含框架与组件库选型、不含组件与 DOM 设计、不含接口契约、不含数据
模型。那些属于设计阶段的下游产物（见 §7）。

### 0.2 信息来源（按可信度排序）

1. **主人的原话与已拍板原则**——本仓库提交历史里被逐条引用过的评价，以及仓库
   `AGENTS.md` 的「界面文案纪律」一节。这是最高权威，本文 §5 与 §6 基本由它构成。
2. **设计文档**——上述四篇。它们是产品决策记录，可以直接采信；本文只转述它们的结论，
   不复制它们的实现细节。
3. **跑起来的界面本身**——本地起网关后用眼睛看：导航怎么分组、一屏放什么、什么密度、
   什么明暗。本文对现状的描述来自看图，不是来自读源码。
4. **后端能力清单**——只读「有哪些面对外」：九个模态、五个工具端点、八家 provider 预设、
   管理面有哪些面（`85-modality-surface-matrix.md` §3 的九张模态卡片与 §4 的工具端点
   卡片是权威清单）。这是产品能力的边界，设计不许越过它发明功能。

### 0.3 一条纪律（本文自己遵守的）

本文**不出现**：组件名、文件路径、目录结构、框架与库的选型结论、DOM 与 class 名、
状态管理方式、接口的字段级形状。需要引用设计文档时只引文档编号与节号，不引代码位置。

## 1. 这个产品是什么

**AgentGateway 是一个自托管的 LLM API 网关。** 客户端可以用任意主流格式
（OpenAI Chat Completions / OpenAI Responses / Anthropic Messages /
Gemini generateContent）发请求，网关负责把请求转成上游 provider 的格式、再把响应
转回客户端格式，并在同一条链路上提供插件、内置工具、用量统计与计费。它跑在主人
自己的机器上，服务的是主人自己的客户端——不是多租户 SaaS。

**这个管理后台是网关的控制面。** 它是管理员（通常就是主人一个人）把网关从「装好了」
变成「能用」的地方：接一家上游、录一把密钥、定一个客户端可见的模型名、发一把客户端
密钥、看今天花了多少、以及用自然语言让网关自己干活。数据面的客户端永远不经过这里，
这里的每一个操作只有两类：「改配置」或「看账」。

**所以它的气质应该接近一件称手的工具，而不是一个功能齐全的系统。** 密度适中、信息
一眼可扫、每个动作都有明确反馈、每个空状态都告诉用户下一步点什么。反面是：把几十个
选项平铺给一个只想确认「今天花了多少钱、有没有报错」的人。

产品能力的边界（设计不许越过）：**九个模态**——对话最完整；语音合成与语音识别已接
两家真实上游；embeddings 与图片生成已有入站脸与编码层、卡在凭据；决策类目前只有
确定性 mock 上游；重排 / 审核 / 视频只有占位。**五个工具端点**（搜索 / 抓取 /
文字识别 / 语音识别 / 语音合成，两家真实上游）。**八家 provider 预设**（四家国际、
四家国内，其中四家预设标着「待验证」，面板上要照实标）。

## 2. 用户要完成的事

按「用户想达成什么」组织，不按页面组织。每条一句话说清目标；同一目标今天由哪一屏
承担不重要，重要的是下次重做时这个目标仍然要被满足。

### 2.1 每天开门就想确认的（高频，读多写少）

1. **网关此刻正常吗、钱在涨吗。** 一屏看到：区间费用、请求数、Token、未定价请求
   四张统计卡（各带一条迷你趋势与环比），成本与请求量两条趋势，按渠道与按模型的花费
   分布，以及系统状态（渠道启用数、凭据健康、别名与密钥条数、密钥存储是否解锁）。
2. **钱具体花在哪了。** 同一份数据的时间范围放大版：更细的范围切换、Token 构成
   （输入 / 输出）、按模型与按渠道的请求数与花费、最近若干条明细、上游余额与对账偏差。
3. **上游余额还够不够。** 主动查一次上游余额，与历史快照对账；偏差超过阈值要显眼，
   不要藏在表格里。

### 2.2 把网关接到一家上游（一次性，配完就不再来）

1. **选一个 provider，出一个属于它的面板。** 从预设里选（或选「自定义」），出现的
   不是一张通用大表单，而是这个 provider 自己的小面板：几条接入端点各一个启用开关、
   一把 key 多路共用、文档链接、备注。
2. **不让用户手打模型 id。** 有自动获取能力的 provider，模型清单由「获取模型」一次
   拉回上游全量元数据（上下文窗口、模态、思考档位、上游声明的约束）；拉取失败要
   说清原因并给可执行动作，不许静默退化成手填。
3. **拉回的清单是一张表，可以搜、可以改。** 模型 id 等宽呈现，元数据缺的字段显示
   「未声明」而不是编一个；默认全选；编辑模式下要能看出「上游新增 / 已有 / 上游已移除」。
4. **保存后的模型清单是快照，不是活链接。** 上游下架模型不该让一个已存渠道的路由行为
   悄悄变掉；要自动同步得是一个显式的高级选项，并说清代价。
5. **看清这个 provider 到底能干什么。** 能力状态三态只读展示：已接入（说什么语义、
   怎么触发）、未接入（说清缺什么）、计划中（一句范围加指向）。不放任何开关——后端
   没有的配置面，画一个能点的开关就是假功能。
6. **自定义 provider 才给完整表单，并明确标注「高级」。** 必填项之外的一切（能力覆盖、
   凭据来源切换）关进默认收起的折叠区——「乱七八糟」只准住在这里。

### 2.3 管好访问上游的钥匙（低频，安全相关）

1. **一把 key 只在创建时出现一次。** 提交后服务端不明文回显；编辑模式不出现 key
    输入框，只有一条「已录入 · 去凭据页管理」的只读行。
2. **同一条接入路径可以有多把 key，坏了自动换。** 每把 key 有掩码、前导位、健康
    状态；用量按凭据记账，对账时能查到每一把。
3. **删除钥匙要确认**，并说明后果。

### 2.4 定客户端可见的模型名（路由的大脑）

1. **客户端写的模型名落到哪，一张表说清。** 三级规则（精确 / 前缀 / 透传），可启用
    可停用，可预览解析结果。
2. **这里不做第二份映射表。** 渠道面板不提供渠道级「模型重定向」——两套映射必然
    漂移；渠道里只放一个「去别名页建规则」的跳转。

### 2.5 让客户端接进来

1. **有哪些模型、什么能力、现在能不能用。** 模型目录与数据面同源：类型、上下文
    窗口、最大输出、可用状态（不可用要写原因），可按类型筛选、可搜索、可从上游同步。
2. **发一把客户端密钥。** 名称、备注、过期时间、可限定模型与 provider；明文只在
    创建响应里出现一次，之后只有掩码；可撤销；可按 key 看用量。
3. **选择器只列能用的项。** 模型下拉里只出现「已启用渠道 + 有可用凭据」的模型；
    一个都没有时那一栏只有一句话加一个主操作（缺渠道去建渠道、缺凭据去录凭据），
    **不画下拉**，也不给「自定义模型…」这种绕过口。
4. **已经存了但当前不可用的值，说清原因。** 设置里的值不删（用户数据，渠道修好它
    该恢复），但呈现为一条只读信息行：「当前保存的是 <值>，<原因>」。

### 2.6 改运行时参数

1. **改完即生效，不用重启。** 每一项标注来源（加密存储 / 环境变量 / 配置文件 /
    内置默认）与是否可改；被环境变量锁定的项只读并给出理由。
2. **「恢复默认」是删掉覆盖，不是把默认值写进去。** 这样来源标签才诚实——删掉后
    它沿四层回落，显示回到「默认」而不是「已修改」。
3. **内置助手的配置和系统参数是同一套机制。** 模型、系统指令、工具开关、高级参数
    都在设置页的同一张表里改；对话页右侧面板与设置页同源，不存在第二份状态。

### 2.7 让网关自己干活（内置对话）

1. **用自然语言管理网关。** 说一句话，它调工具查渠道、查凭据、查模型、建渠道、
    发密钥、汇总用量、解析别名、测渠道。工具调用全程可见（工具名 / 状态 / 入参 /
    结果摘要），出错的调用用危险色标出。
2. **它永远看不到密钥。** 任何工具结果进模型前不含完整密钥（掩码、长度、前导位
    可以给）；用户贴在对话里的密钥形态串在发送前就被替换成占位符，输入框实时高亮
    并提示「将以 <占位符> 发送」。
3. **需要密钥时弹窗要，不给模型。** 模型只能拿到「需要凭据」这个状态；key 由用户
    填进弹窗，直接走既有的凭据创建端点；对话请求体里没有任何密钥字段。
4. **思考过程可看可折。** 推理模型的思考内容折叠成一行摘要，展开看全文；上游不给
    思考内容时整行不渲染（不是显示一个空的「思考」）。
5. **一轮干了什么、花了多少 token，看得见。** 回合顶部一条过程条（耗时 / 消息数 /
    工具数），失败与停止有各自的文案；token 用量按「有才渲染」的分桶行呈现。
6. **会话可以翻历史、可以删。** 留存默认关闭；关闭时列表空态直接说「未开启会话
    留存」加一个「去设置」的主操作，不假装有历史；删除走确认弹窗。

### 2.8 规则与代价的完整说明

1. **帮助页是解释性文字唯一的家。** 每个功能页只放一句话加一个「了解更多」深链；
    帮助页每节标注出处（设计文档章节或实现文件），可搜索。
2. **没接上就说没接上。** 帮助页里有「尚未实现 / 待定」的清单（例如某些端点属于
    待定项），界面不为难看的现状编说法。

## 3. 信息架构建议

### 3.1 现状分组与它的问题

现状（改版后、单子项组拍平后）是五组：概览 / 对话 / 上游接入（渠道 · 凭据 ·
别名映射）/ 模型与用量（模型目录 · 用量看板）/ 系统（客户端密钥 · 系统设置 ·
安全与密钥 · 帮助）。默认落地页已从「渠道」改成「概览」，单子项分组已拍平
（`90-admin-ui-redesign.md` §3.1 记的那一版是九个平铺页、默认落在渠道）——
这两条是对的，别再退回去。

剩下的三个问题：

1. **「系统」是个抽屉。** 客户端密钥回答的是「客户端怎么接进来」，和「系统设置」
   「安全与密钥」「帮助」不是一类问题。把它塞进系统组，等于让客户端最常问起的
   那把钥匙埋在最后一个折叠组里。
2. **「别名映射」放错了组。** 它是客户端可见模型名的路由表，是**面向客户端**的契约，
   却和渠道、凭据这些**面向上游**的配置并列。上游接入组因此混了两个方向的问题。
3. **「模型与用量」把两个问题捆在一起。** 「有哪些模型、什么能力」是能力清单，
   「花了多少、怎么花的」是账。两者关联确实紧（能力结构决定花费结构），可以保留
   同组，但组内顺序应当是「先能用什么，再花了多少」。

### 3.2 建议的分组

按管理员提问的频率与方向分六组，每组至少两项（单子项组一律拍平，见 §5 第 4 条）：

| 组 | 条目 | 回答什么问题 |
| --- | --- | --- |
| 概览（一级，默认落地） | 概览 | 网关此刻正常吗、钱在涨吗 |
| 对话（一级） | 对话 | 用自然语言让网关自己干活 |
| 上游接入 | 渠道 · 凭据 | 请求打到哪个上游、用哪把 key |
| 客户端接入 | 客户端密钥 · 模型别名 | 客户端用什么 key 进来、写什么模型名 |
| 模型与用量 | 模型目录 · 用量看板 | 有哪些模型能用、花了多少 |
| 系统 | 系统设置 · 安全与密钥 · 帮助 | 运行时参数怎么配、密钥存储什么状态、规则去哪查 |

与现状的差异只有两处：客户端密钥从「系统」移到新的「客户端接入」组，别名映射从
「上游接入」移到同一组。改完之后每一组内部只回答一个问题，两个接入方向各得其所。
分组名要能被非技术管理员一眼看懂，不要用内部模块名当组名。

### 3.3 默认落地页

保持「概览」。理由不是抄谁，而是两类信息的读取频率不同：渠道 / 凭据 / 别名是一次性
配置，看完就不再来；「今天花了多少、有没有报错」是每次开门都想确认的。把低频配置页
当主场，等于让管理员每次开门都先翻过一屏用不到的东西。

时间范围等筛选状态要进 URL，刷新与分享链接不丢状态；图表可以下钻到带同一筛选的
用量页。

### 3.4 已知缺口：不许发明数据

后端今天**没有**记录的东西，界面不许画出来，也不许用假的形状充数。缺数据源时放一张
说明卡，写清缺什么、为什么不能退而求其次（例如不能把「没有错误率数据」画成 0%——
0% 会把一次故障藏起来）：

- **每次请求的耗时与状态码**（于是没有延迟分位图、没有错误率时序）；
- **请求级日志页**（于是没有「图表 → 日志」的带筛选下钻，没有实时尾巴）；
- **缓存读 / 写 token 的拆分**（于是没有缓存命中率）；
- **per-request 的路由轨迹**（于是没有分流桑基图）；
- **历史基线存储**（于是没有异常检测）。

这些是后端补齐后的二期 / 三期候选，不是本次设计的范围；但**设计要把位置留出来**，
不要用别的图表把坑填掉。

## 4. 风格与气质

### 4.1 对标与不象

**对标：Linear / Vercel / Resend 这一系的现代工具型界面。** 共同语法：中性优先的
表面（无彩度画布 + 一个克制的强调色）、深度靠「表面阶梯 + 1px 发丝边」而不是投影
浓度、圆角 6–14px、紧凑字阶（12/13/14/16，权重只用 400/500/600/700 四档）、表格与
统计数字用等宽数字、暗色是一等公民。主人对上一版的原文是「样式不现代，和上世纪的管理
界面一样，起码要超过 NewAPI 目前的界面」，外加两条具体要求：「用量界面还没做图表展示」
和「先调研加入什么功能、怎么分 Tab、怎么展示」。

**不象：**

- **上世纪的管理界面。** 饱和蓝色主色、一屏纯白、3px 圆角、1px 黑边投影、四边带框的
  表格、2px 粗表头下边框——这是被明确否掉的一版观感，任何一条都别再回来。
- **NewAPI 旧版。** 它是「要超过」的参照系，不是「要对标」的风格源。超过它的方式是
  补它没有的维度（延迟 / 错误率 / 下钻 / 异常检测），不是把它的界面抄得更花。
- **AI 味的视觉。** 渐变、玻璃拟态、大圆角卡片堆叠、霓虹强调色、无意义的入场动画——
  这是一件工具，不是一张海报（注意：现状对话页的 hero 已经带了一处四色弥散光晕，
  见 §4.6，那是要拍板的遗留，不是本简报的主张）。
- **多租户 SaaS 的繁重。** 角色矩阵、权限树、组织 / 团队 / 项目层级——这个部署只有
  管理员一类人，不为想象中的多用户设计。

### 4.2 排版与密度

- **密度中等偏疏，一屏一件事。** 概览不放明细表；一张卡说一件事；卡与卡之间用间距
  呼吸，不用边框互相切。
- **字号与间距要「放大一档」。** 主人对上一版的原文是「排版小气，间距 / 字号 / 行高
  都偏小」。可用的刻度锚点：正文 14px、次级说明 13px、卡片标题 15px、面板分区标题
  16px、页面标题 24px、统计卡大字 28px；卡内边距 24px、卡间距 20px、表格行高约 56px、
  输入框与按钮高约 36px；正文行高 1.7。
- **标题层级差要一眼可辨。** 相邻层级至少差一档字号加一档字重；不允许出现「两个层级
  大小几乎一样」的组合。
- **等宽数字。** 并排的统计卡位数变化时整行不抖。
- **标识符一律等宽。** 模型 id、接入路径、上游地址用等宽字体呈现，和正文拉开。

### 4.3 色彩与明暗

- **一个强调色，克制使用。** 主色只给主操作与选中态；状态色另有一套，不混。
- **状态五档 + 三编码。** 成功 / 警告 / 危险 / 信息 / 中性五档语义；每个状态除了颜色
  还有一个形状线索与文字标签——颜色永远不是唯一编码。
- **环比颜色按指标定，不按涨跌方向定。** 同一个上升箭头在费用卡上是坏事、在请求量
  卡上是好事。
- **明暗三档：亮 / 暗 / 跟随系统（默认）。** 偏好存本地；会话令牌不存本地，两者不冲突。
- **暗色不是亮色取反。** 画布取近黑（纯黑上发丝边会闪），表面比画布亮一档，状态色
  整体提亮（暗底上同色值对比度会掉）。

### 4.4 动效尺度

- **短、轻、有理由。** 时长 120–240ms；只做淡入、位移、按压反馈；没有弹跳、没有
  旋转加载圈、没有渐变、不堆阴影。
- **加载态分层。** 整页首载用与真实布局同形的骨架屏；单卡刷新用就地指示；响应快于
  一秒不显示加载态；自动刷新保留旧数据并标「陈旧」，不重新骨架化。
- **尊重系统设置。** 用户要求减少动效时，位移与过渡全关。

### 4.5 两种气质：管理台页与对话页

**要，而且应该分开。**

- **管理台页**（概览 / 渠道 / 凭据 / 目录 / 用量 / 设置 / 安全）是**仪表盘气质**：
  表格、图表、状态标签，密集但可扫；用户来这里是「看」和「配」。
- **对话页**是**工作台气质**，对标 AI Studio 的 Playground：三栏（侧栏导航 / 对话区 /
  右侧运行设置），底部一条通栏输入栏永远在视线内；空状态是一句 hero 加三个可点击
  示例（点了直接发送）；用户来这里是「说」。主人的原话是「你这 UI 难评……生怕我能用
  是吗」，这一页就是照那个反馈重做的，方向不要再退回去。
- **两者共用同一套令牌**（画布 / 表面 / 边框 / 文字层级 / 强调 / 状态 / 圆角 / 时长），
  不许出现两套并存的皮肤——那是「抄了皮肤丢了底色」。
- 右侧「运行设置」与系统设置页**同源同数据**：改面板就是改设置，不存在第二份状态
  （这条同时是 §5 第 5 条「数据驱动」的要求）。

### 4.6 现状里待定的风格决策（下一次要拍板）

上一轮把对话页按 AI Studio 的参照重做时，顺带改动了几个**全站级**的风格量，于是现状
里同时存在两套主张。下一次动手前，这几条要先有答案：

1. **一个强调色。** 管理台页的既有方案是一档低彩度的蓝紫；AI Studio 化又把全局主色
   换成了参照系的那一档亮蓝。两套主张不可能同时成立——全站只能有一个强调色，且它
   要同时在仪表盘页与对话页上成立。
2. **品牌字标。** 侧栏头部现在写着「AgentGateway」，下面挂一行参考系的名字。穿着
   参考系的名字会让用户以为这是别人的产品。要么用自己的产品名，要么明确这是致意，
   但不能含糊。
3. **中英混排。** 对话页的页题与 hero 文案是英文，所有功能标签是中文。这是「控件
   文案不超过十二个汉字」的纪律与 AI Studio 观感折中的结果，但它需要成为一条明写的
   规则（哪一类文字允许用英文、其余一律中文），而不是各页自由发挥。
4. **装饰光晕。** 对话页 hero 背后那处四色弥散光晕，与「工具不是海报」相冲。留或
   不留请主人拍板；留的话，管理台页不许有第二处。

## 5. 交互硬约束

以下每条都是主人已经拍过板的原则，**不许再商量**。前四条有机器红线守着
（界面文案扫描脚本，未豁免的疑似直接红灯），其余由契约测试与 review 守。

1. **界面上只允许四种文字**：字段标签、placeholder、必要的短 Tooltip、错误 / 成功
   反馈（含空状态的「一句话 + 主操作按钮」）。整段讲解一律不张贴在界面上。
2. **解释性内容只住在帮助页。** 有长期价值的移入帮助页对应小节，功能页上放深链指过去；
   纯冗余的删掉。帮助页每节标出处。
3. **内部术语不许出现在用户可见串里。** 用户不该看见流水线阶段、格式方言、编解码、
   密钥封装相关的内部名词——一个都不行。
4. **单子项导航分组一律拍平。** 一级菜单只有一个项目，就不需要那一级；拍平只改层级，
   不改深链。主人的原话：「一级菜单只有一个项目，那为啥还需要一级菜单」。
5. **数据驱动：系统里有的清单，不许让用户手填。** 有模型列表与能力矩阵，选模型就是
   下拉，不是文本框；新接一家 provider 只是加一条预设数据，不是加一段分支逻辑。
6. **没配就是没有，不要想方设法列出来。** 不可用的项不进选择器（不是置灰留着）；
   零可用时那一栏只有一句话加一个主操作，不画下拉，不给绕过口；已存但不可用的值
   呈现为只读信息行（值 + 原因），不是下拉里的一个选项。
7. **不画假功能。** 后端没有配置面的开关不画；能力状态三态只读；「写了没处存」的
   控件就是假功能。
8. **状态文案诚实。** 桩功能就说它是桩，不用「测试」「连通」这种没发生的词；探测
   按钮要么真的打一次上游，要么改名说清它只做什么。
9. **空状态 = 一句话 + 一个主操作。** 不许第二、三句解释；请求在飞时绝不显示
   「没有数据」——那是错误的系统状态。
10. **错误必须可操作。** 说清发生了什么 + 下一步点什么；按失败原因分类（认证 /
    权限 / 路径不存在 / 限流 / 网络 / 上游故障），每类一条动作；错误文案里绝不出现
    密钥或完整响应体（细节进可展开的「详情」）。
11. **密钥只从界面弹窗进加密库。** 创建时一次提交、不明文回显、不进日志、不进错误
    信息；模型永远看不到密钥材料；用户贴进来的密钥形态串在发送前就被替换；脱敏以
    服务端为权威，前端预览只是同一规则的提前呈现。
12. **「恢复默认」= 删掉覆盖。** 让值沿「加密存储 / 环境变量 / 配置文件 / 内置默认」
    四层回落；来源标签照实显示，被环境变量锁定的项只读并给出理由。
13. **破坏性操作要确认**（删除、撤销、轮换主密钥），并说明后果。
14. **图表纪律。** 不用饼图 / 环形图 / 仪表盘 / 双轴 / 彩虹分类色 / 平均延迟；空桶
    与「无数据源」是两件事；缺数据源放说明卡，不造假数据；计数类指标的轴从 0 开始；
    关键数值不允许「只有鼠标能看到」——提示浮层里的数字在统计卡或表格里必须有对应。
15. **筛选状态入 URL**，刷新与分享不丢。
16. **动效尊重系统的减少动效设置**，见 §4.4。

## 6. 反面清单

被主人明确否掉的东西，以及不许再出现的模式：

1. **整版推倒重写。** 那版换了一套前端框架与组件库、把管理后台整体重写的产物，
   主人看完只给了一个字：「垃圾」。教训不是某个框架不好，而是**整体重写不产生重新
   设计**——它只会把旧结构翻译成新语法。被接纳的那条路恰恰相反：不换框架，在既有
   产物上按参照系把**呈现**重新想一遍（对话页那次就是这么过的）。下一篇要做的是
   重新想，不是重写。
2. **「上世纪管理界面」观感。** 饱和蓝主色、一屏纯白、3px 圆角、1px 黑边投影、
   全边框表格。见 §4.1。
3. **九个平铺导航 + 默认落地页是渠道。** 管理员开门第一眼看到上游配置，而不是
   「网关跑得怎么样」。
4. **一个通用大表单服务所有 provider。** 主人原话：「每个 provider 都是自己的配置
   界面，这样简洁明了，并且还可以给出额外的信息进行更多配置；只有用户选择 Custom
   才去配置各种乱七八糟的。」
5. **手填模型 id。** 「provider 这里还是需要我自己输入一个个 id」；以及主人试用对话页时
   贴出的截图 4：「明明系统都有模型列表了，结果还要我自己手填也是绝了」。
6. **界面上整段讲解。** 「文字无重点，很多讲解文字完全没必要」。
7. **排版小气。** 13px 正文、18px 卡内边距、标题层级只差几像素。
8. **「测试连通性」按钮不发起上游请求。** 文案不诚实——连通性由一次真实的上游调用
   （获取模型）证明，或者按钮改名说清它只做什么。
9. **给未接入的能力画开关。** 假功能比没有功能更糟。
10. **在选择器里置灰保留不可用项 + 给「自定义模型…」绕过口。** 主人原话：「为啥还有
    deepseek-flash，他是你亲爹吗？」「直接告诉用户没有模型去配置不行吗？」
11. **把什么都塞进一个抽屉 / 弹窗。** 参照系的渠道抽屉是五千行的单体——「什么都塞进
    一个抽屉」正是「乱七八糟」的来源。面板要按 provider 拆散，一家一个小而完整。
12. **换框架替代审美。** 参照系自己迁到新框架之后，社区对新界面的评价是「写的人还
    一点审美没有」。能超过它的是信息维度与密度，不是样式方案。
13. **图表里的坏味道。** 双轴、饼 / 环图、仪表盘、平均延迟、渐变玻璃拟态、弹跳动效。
14. **两套设计令牌并存。** 抄了皮肤丢了底色；借结构可以，借令牌名不行。

## 7. 这份简报不包含什么

明确声明，免得下一个设计者在这里找它：

- **不含实现选型。** 前端框架、组件库、状态管理、构建工具、图表库——一概不在本文
  决定，也不因本文的任何表述被默认决定。
- **不含组件设计与视觉规格。** 组件清单、属性、DOM 结构、class 命名、令牌取值属于
  设计阶段的产出。
- **不含接口契约。** 端点、请求 / 响应形状、字段名与类型属于设计阶段与后端设计。
- **不含数据模型与存储设计。** 存什么、怎么加密、保留多久属于既有设计文档的范围。
- **不含测试方案与验收脚本。** 属于实现计划。

本文只回答四个问题：**这是什么、要帮用户完成什么、看着是什么气质、哪些行为已经
拍过板。** 剩下的等设计阶段。
